# Kubernetes GitOps Homelab

This repository is a curated, public-safe snapshot of a homelab Kubernetes GitOps platform. It demonstrates how I structured cluster configuration around Flux, Kustomize, HelmRelease resources, ingress, DNS, monitoring, certificate management, and sealed-secret workflows.

## Project Status

This is a learning and portfolio repo, not a production environment. Live secrets, kubeconfigs, cluster-specific bootstrap credentials, and generated Flux controller manifests have been intentionally removed or replaced with examples. The original private lab kept the operational history; this public version focuses on the architecture and practices worth showing.

## Architecture

```text
GitHub repository
  |
  | Flux GitRepository + Kustomization
  v
Cluster reconciliation
  |
  +-- infrastructure/
  |   +-- sources: Helm repositories
  |   +-- namespaces: shared namespaces
  |   +-- cert-manager: internal certificates
  |   +-- monitoring: kube-prometheus-stack and ingress
  |   +-- sealed-secrets: secret encryption controller
  |   +-- dns: CoreDNS records for lab service names
  |
  +-- apps/
      +-- Open WebUI application
      +-- Tailscale subnet router
```

## What This Shows

- GitOps reconciliation with Flux and Kustomize.
- Environment structure for cluster infrastructure and application workloads.
- HelmRelease-based platform components for monitoring and sealed secrets.
- Internal DNS and TLS patterns for a private Kubernetes lab.
- Secret handling patterns that avoid committing live credentials.
- Remote access design using Tailscale subnet routing.

## Repository Layout

```text
clusters/production/       Flux entrypoint for the production lab cluster
infrastructure/            Cluster services: sources, monitoring, DNS, certs, namespaces
apps/production/           Application workloads reconciled by Flux
examples/                  Public-safe secret examples that are not applied automatically
```

The large `gotk-components.yaml` generated by `flux bootstrap` is omitted from this public snapshot. In a live cluster, Flux can regenerate controller components during bootstrap.

## Secret Handling

The applied manifests reference Kubernetes Secrets by name, but this repo does not include live secret values. For a real deployment:

1. Create local Secret manifests with the required keys.
2. Seal them with `kubeseal` or sync them through an external secret manager.
3. Commit only the encrypted SealedSecret output or manage the secret outside Git.

Example non-applied manifests live in `examples/`.

## Operational Lessons

- GitOps makes cluster drift visible, but generated bootstrap output should be separated from the human-authored platform config.
- SealedSecrets are useful for a homelab, but key rotation and cluster rebuilds need a recovery plan.
- Internal service names and private CIDRs are fine for a lab, but public repos should clearly mark them as examples.
- Monitoring and ingress are more readable when documented as platform layers instead of scattered manifests.
